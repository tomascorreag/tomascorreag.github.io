## High Priority Issues

### [H1] `skip()` resolves a promise that may not exist yet
- **File:** `src/components/ParticleMorph.js` — `skip()` method
- **Description:** `enableSkipMorphOnClick(morph)` attaches the click listener *before* `morph.start()` is awaited. `resolveStart` is assigned inside `start()`'s Promise executor — if the user clicks between those two lines, `this.resolveStart` is `undefined`, the call is a no-op, and `await morph.start()` hangs forever.
- **Suggested Fix:** At the top of `start()`, assign a no-op before returning the Promise:
```js
start({ source, target, container, color }) {
  this.resolveStart = null;
  return new Promise(resolve => {
    this.resolveStart = resolve;
    // ... rest
  });
}
```

## Warnings

### [W1] Stagger timeouts leak on rapid category switching
- **File:** `src/main.js` — `renderMosaic()` (~line 597)
- **Description:** `setTimeout` closures hold refs to DOM nodes that may be removed by `mosaicEl.innerHTML = ''` before they fire (~2.1s window for 10 elements). Old + new timer sets run concurrently if user switches back to General fast.
- **Suggested Fix:** Store IDs and cancel on next `renderMosaic()` call:
```js
let staggerTimeouts = [];
// at start of renderMosaic():
staggerTimeouts.forEach(clearTimeout);
staggerTimeouts = [];
// replace forEach:
staggerTimeouts = targets.map((el, i) =>
  setTimeout(() => el.classList.add('visible'), i * 210)
);
```

### [W2] `innerHTML` with data from `gc.tools` and `skill.label/detail`
- **File:** `src/main.js` — `renderGeneralContent()` (~lines 652, 703)
- **Description:** Skills and tools are rendered with template literals into `innerHTML`. Not a vector today (static config), but inconsistent with the rest of the diff which correctly uses `textContent`. A future contributor adding `"C# & <script>…</script>"` to the tools array would execute it.
- **Suggested Fix:** Use `textContent`:
```js
for (const t of gc.tools) {
  const span = document.createElement('span');
  span.className = 'general-tool';
  span.textContent = t;
  toolsRow.appendChild(span);
}
```
Same pattern for skill label/detail.

### [W3] `startTypeout()` doesn't clear a running interval before starting a new one
- **File:** `src/main.js` — contact copy block (~line 752)
- **Description:** `startTypeout()` doesn't guard against an already-running `typeInterval`. If called while one is active, the old interval orphans. Currently protected by the `copied` guard but defensive clearing costs nothing.
- **Suggested Fix:**
```js
const startTypeout = () => {
  if (typeInterval) { clearInterval(typeInterval); typeInterval = null; }
  charIndex = 0;
  // ...
};
```

### [W4] `rel="noopener"` missing `noreferrer` on external links
- **File:** `src/main.js` — contact link block (~line 797)
- **Description:** `noopener` alone doesn't suppress the `Referer` header — the new page receives your portfolio URL. Best practice for `target="_blank"` is both.
- **Suggested Fix:**
```js
a.rel = 'noopener noreferrer';
```

### [W5] Debug tier override is active in production
- **File:** `src/config/device.js` — lines 116–118
- **Description:** Any visitor can append `?tier=low` to force a degraded experience. The console warning is DEV-only, so in production the override is silent. Unlikely to be exploited but could cause confusing production debugging.
- **Suggested Fix:** Gate behind `DEV`:
```js
const _debugTier = import.meta.env.DEV
  ? new URLSearchParams(window.location.search).get('tier')
  : null;
```

### [I5] `color-mix(transparent)` is not identical to `opacity: 0.2`
- **File:** `src/style.css` — `.general-divider`
- **Description:** `transparent` = `rgba(0,0,0,0)`, so the mix produces a black-tinged semi-transparent color rather than a pure alpha of the text color. Visually acceptable but not a 1:1 replacement. Using `color-mix(in srgb, var(--text-primary) 20%, rgb(0 0 0 / 0))` would be more semantically equivalent.
